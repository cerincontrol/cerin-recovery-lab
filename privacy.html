Privacy policy

This policy describes how CERIN Recovery Lab is designed to access and handle Google Drive data during private, nonproduction recovery exercises.

Last updated: 25 October 2026

1. Operator and purpose

CERIN Recovery Lab is a privately operated, noncommercial utility intended to validate encrypted backup retrieval and signed-journal integrity. It is designed for use by authorized operators, not the general public. It is not a consumer cloud-storage or account-aggregation service.

The laboratory is intended to use synthetic test records. Production research measurements, production backup credentials and other live CERIN Control data should not be copied into the laboratory.

2. Google account and Drive access

When an operator authorizes the rclone application through Google OAuth, the application may receive permission to access files in Google Drive on the operator's behalf, according to the selected authorization scope:

  • Upload authorization: Google Drive file access, such as the drive.file scope, for publishing synthetic laboratory artifacts.
  • Recovery authorization: drive.readonly for retrieving test artifacts without granting write access. This scope can permit reading all Drive content available to the authorizing Google account, even when the operator intends to use only one folder.

Actual access depends on the consent granted by the operator and the Google identity used. A folder path or rclone root-folder setting alone does not enforce a Google-account-level permission boundary.

3. How Google user data is used

Authorized Drive access is intended exclusively for locating, uploading, downloading and verifying encrypted synthetic recovery-test packages and checking their integrity. Files may be temporarily decrypted locally to validate checksums and signed journal checkpoints.

Google user data is not used for advertising, profiling, targeting, data brokerage or unrelated model training. The website itself does not request Google account authorization or process Google Drive contents.

4. Storage and security

Encrypted synthetic packages are intended to be held in a dedicated laboratory folder in the operator's Google Drive. OAuth tokens and rclone configuration files are intended to be kept in restricted files or a separately safeguarded secrets vault on the operator's own computers. Encryption keys are intended to be separate from production backup keys.

Recovered test files may be stored briefly on an isolated workstation for offline verification. No OAuth secrets, encryption passphrases, unencrypted journal records or account tokens should be committed to the publicly accessible website repository.

No storage system can be guaranteed perfectly secure. Operators should use least-privilege accounts, device security and independent credential backup.

5. Data sharing and Google's Limited Use requirements

The laboratory is not intended to sell, rent or disclose Google user data to third parties. Google Drive is the storage and identity provider selected by the operator; rclone is the local transfer application. Operators may separately elect to publish non-sensitive trust-anchor hashes and test summaries as technical evidence.

Use of information received from Google APIs is intended to comply with the Google API Services User Data Policy, including its Limited Use requirements. Drive content is not transferred to advertising services.

6. Retention and deletion

Synthetic test packages should be retained only for the period required to validate and document the rehearsal, then deleted by an authorized operator under a separately approved cleanup procedure. OAuth configurations and local copies should be deleted securely when no longer needed, subject to the operator's retention requirements.

Revoking OAuth access does not itself delete files previously uploaded to Google Drive; those files must be deleted separately by an authorized operator. This policy does not grant automatic deletion authority to the recovery tooling.

7. Revoking Google authorization

The Google account holder can revoke the application's access in Google Account → Third-party connections. Local rclone tokens should also be removed from the operator's protected configuration. Once access is revoked, the affected connection may stop working until separately reauthorized.

8. Visitors to this website

This static site has no account-registration feature, cookies set by the site code, advertising integrations, analytics scripts, contact forms or tracking pixels. It does not itself collect Google account data. GitHub Pages, as the hosting service, may process technical connection information under GitHub's own privacy practices; see GitHub's privacy statement.

9. Contact and policy updates

Questions about this laboratory's data-handling practices can be raised with the maintainers via the project's GitHub issue tracker. Do not include credentials, tokens, private keys or personal data in public issues.

This policy may be updated to reflect changes in actual permissions, operations or infrastructure. Material changes should be reflected on this page before the corresponding change is used.
